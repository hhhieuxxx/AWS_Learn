## Features

- **Storage Classes**: Cung cấp nhiều lựa chọn lưu trữ phù hợp với nhu cầu truy cập, độ bền và thời gian lưu trữ, giúp khách hàng tối ưu chi phí.

- **Storage Management**: Hỗ trợ các tính năng quản lý như Life Cycle, Object Lock, Replication và Batch Operations.

- **Access Management**:  
  Quản lý quyền truy cập thông qua:

  - Resource permission
  - Access list
  - IAM
  - Bucket policy
  - S3 access point
  - ACL
  - Ownership
  - Access Analyzer

- **Data Processing**:  
  Tích hợp với các dịch vụ như Lambda, SNS, SQS để xử lý dữ liệu nhanh chóng.

- **Auto Logging & Monitoring**:

  - Tự động ghi log với **AWS CloudTrail**
  - Công cụ theo dõi thủ công: **Log record in bucket**

- **Analytics & Insights**:  
  Phân tích và tối ưu dữ liệu.

- **Strong Consistency**:  
  Đảm bảo tính nhất quán mạnh mẽ trong việc ghi và đọc dữ liệu.

## Use Cases

- Lưu trữ file cho các ứng dụng chạy trên EC2, Container, Lambda.  
  Các file có thể đa dạng về loại & kích thước (Image, Video, Document,...)

- Lưu trữ/archive log cho các dịch vụ AWS khác như VPC, ALB, API Gateway,...

- Làm **data source** cho các bài toán **Big Data & Data Warehouse**

- Lưu trữ dữ liệu gửi từ các thiết bị **IoT**

- Làm vùng lưu trữ tạm thời cho **ETL workflows** (Extract - Transform - Load), thường kết hợp với Lambda

- **Host website tĩnh** (HTML, CSS, JS) khi kết hợp với **CloudFront**

## Bucket Policy & Access Control List (ACL)

### Bucket Policy

- S3 hỗ trợ **Resource-Level Policy** bên cạnh IAM Policy.
- Bucket Policy hoạt động tương tự IAM Policy nhưng chỉ áp dụng trong phạm vi bucket và các object bên trong.
- Bucket Policy có thể **allow** hoặc **deny** quyền truy cập.
- Phù hợp với các bucket yêu cầu độ bảo mật cao, cần giới hạn quyền truy cập chặt chẽ.

### Access Control List (ACL)

- ACL quy định quyền truy cập của một **AWS Account** hoặc **Group** đến bucket hoặc object.
- Dùng khi cần cấp quyền cho một resource cụ thể mà không muốn thay đổi bucket policy.
- **Lưu ý**:  
  AWS hiện **khuyến nghị KHÔNG sử dụng ACL**, trừ khi thật sự cần thiết.  
  Thay vào đó nên dùng:
  - Bucket Policy
  - IAM Policy
  - Pre-signed URL

## Storage Classes

S3 cung cấp nhiều storage class khác nhau nhằm giúp người dùng linh động trong việc lựa chọn class phù hợp với nhu cầu, tiết kiệm chi phí.
Việc lựa chọn class phụ thuộc vào các yếu tố như:

- Durability, High Availability
- Thời gian lưu trữ (1 tháng ăm, 5 năm...)
- Tần suất truy cập, thời gian cân có file khi có yêu cầu
- Mục đích sử dụng: document, image, log file, backup file, archive

Type:

- _S3 Standard_: Mặc định, phù hợp cho hầu hết các trường hợp sử dụng với độ sẵn sàng 99.99%.
- _S3 Intelligent Tiering_: Tự động giám sát tần suất truy cập và điều chỉnh cấp lưu trữ để tối ưu chi phí, áp dụng cho đối tượng ≥128KB, có thêm phí giám sát.
- _S3 Standard Infrequent Access (IA)_: Phù hợp cho dữ liệu ít truy cập nhưng cần truy xuất nhanh, độ sẵn sàng 99.9%.
- _S3 One-Zone IA_: Rẻ hơn 20% so với Standard IA, chỉ lưu trữ trong một AZ, độ sẵn sàng 99.5%, phù hợp cho dữ liệu có thể tái tạo dễ dàng.

- _S3 Glacier_: Phù hợp cho việc lưu trữ dữ liệu trong nhiều năm nhưng ít khi được sử dụng.

  - Glacier Instant Retrieval

    - Rẻ hơn **68%** so với **S3 Standard IA**.
    - Truy xuất nhanh chóng khi cần.
    - Phù hợp cho dữ liệu như hồ sơ phim, hình ảnh y tế cần truy xuất ngay.

  - Glacier Flexible Retrieval (Normal)

    - Phù hợp cho dữ liệu **không yêu cầu truy xuất ngay**.
    - Thời gian truy xuất từ **vài phút đến vài giờ**.
    - Thích hợp cho **backup** hoặc **lưu trữ**.

  - S3 Glacier Deep Archive
    - Lưu trữ lâu dài từ **7-10 năm**, theo tiêu chuẩn ngành tài chính, y tế, v.v.
    - Dữ liệu lưu trên **băng từ (magnetic tape)**.
    - AWS cam kết truy xuất dữ liệu trong vòng **12 giờ**.

- _S3 on Outposts_: Cho phép sử dụng **S3** trên **on-premise**.

## Lyfe Cycle

Tính năng cho phép tự động move object _xuống_ các class lưu trữ thấp hơn hoặc xoá luôn sau một khoảng thời gian nhằm tiết kiệm chi phí.

Khác với Intelligent Tiering, người dùng sẽ tự quyết định life cycle cho objects (hoặc 1 thư mục), vd sau 90 ngày thì cho xuống Glacier, sau 270 ngày thì xoá hoàn toàn.

Phù hợp cho các bài toán lưu blog đã biết trước thời gian thường xuyên access và thời gian có thể xoá.

## S3 Static Website Hosting

S3 có hỗ trợ người dùng host 1 website tĩnh (chỉ bao gồm html, css, js, image...)
Được thừa hưởng toàn bộ đặc tính của S3 (Durability, HA)
Không cần duy trì server, giảm effort Administration.
Hỗ trợ setting CORS nhằm tránh tài nguyên bị khai thác bởi website khác.
Kết hợp với dịch vụ CDN (CloudFront) có thể giúp tăng tốc độ truy cập khi user nằm ở các region khác nhau.

## S3 event trigger

S3 cung cấp cơ chế trigger 1 event sang dịch vụ khác khi có thay đổi đối với object (upload, delete)
Target của trigger có thể là Lambda Function, SNS, SQS.

- Resize image khi có người uplo page lên s3 bucket, lưu vào các thư mục size khác nhau
- Giải nén 1 file zip khi có người upload.
- Extract csv file, xử lý data rồi lưu vào database
- Notification tới Operator khi có ai xoá 1 file

## Best practices for S3

Chọn region của S3 cùng region với application (EC2, ECS) để tối ưu performance.
Sử dụng bucket policy cho những data quan trọng. Cấp quyền vừa đủ cho user/role, hạn chế cấp S3FullAccess.
Bật versioning để bảo vệ data tránh bị mất, xoá nhầm.
Mã hoá data nhạy cảm (client side or server side).
Enforce TLS để yêu cầu sd HTTPS khi truyền nhận file (chống hack).
Sử dụng VPC endpoint để tăng tốc truy cập từ application (sẽ học ở bài VPC).
Khi host static web, nên kết hợp với CloudFront để tối ưu chi phí và tăng trải nghiệm người dùng.
